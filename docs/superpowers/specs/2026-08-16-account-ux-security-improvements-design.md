# 账号安全与体验改进设计（注销强制复核 / 密码强度 / 注册跳转 / 记住凭据）

> 日期：2026-08-16 ｜ 状态：设计稿 ｜ 范围：后端 + 前端

## 1. 目标

1. 把「敏感操作二次认证」落到最不可逆操作上：**注销账号、删除用户、批量删除用户不受 30 分钟免复核窗口豁免，必须当场同时输入「当前密码 + 任意一种 2FA 验证码（邮箱验证码或 TOTP）」**；其余敏感操作保留现有「密码复核 + 30 分钟窗口」。
2. 密码输入框实时显示**密码强度**（弱/中/强）。
3. 账号**注册完成后自动跳转登录页**。
4. 登录页提供**「记住账号」「记住密码」**选项并落地。

## 2. 现状

- 注销/删除类端点当前走 `authorize_stepup`：30 分钟窗口内可免密码执行注销（上一轮 step-up 功能的设计取舍）。
- 注册成功跳转 `/verify-email`；登录页无邮箱预填，仅「记住我（30 天内免登录）」。
- 密码输入框只有 `minLength=8`，无强度反馈。

## 3. 方案

### 3.1 注销类操作强制「密码 + 任意 2FA」复核

后端三个端点在校验前强制要求 `current_password` 非空（窗口不豁免）：

| 端点 | 缺密码响应 |
| --- | --- |
| `POST /api/v1/me/delete` | 400「注销账号必须输入当前密码并完成二次验证」 |
| `POST /api/v1/admin/users/{id}/delete` | 400「删除用户必须输入当前密码并完成二次验证」 |
| `POST /api/v1/admin/users/batch/delete` | 400「批量删除必须输入当前密码并完成二次验证」 |

新增 `POST /api/v1/me/step-up/send`：向绑定邮箱发送用于复核的 2FA 验证码（复用 OTP 发送冷却与每小时配额）。复核校验顺序：

1. `current_password` 非空且校验通过（沿用 step-up 密码复核的限流与审计）；
2. `stepup_method ∈ {email_otp, totp}` + `stepup_code` 非空，二码验证通过（邮箱码走 `OtpPurpose.two_fa` 的 `verify_otp`，自带 5 次尝试锁；TOTP 走 `verify_totp`，另加按邮箱的失败限流）；
3. 校验成功才执行注销/删除；任一失败返回对应 400/429。

前端对应弹窗改为「密码 + 二次验证方式 + 验证码（含“获取邮箱验证码”）」的复合复核表单，始终必填、不走 30 分钟窗口。

取舍：注销/删除账号不可逆且直接抹掉全部数据，是最高危动作；30 分钟窗口与单因素密码都不足以覆盖「会话被窃取后静默注销」的风险，因此单独要求双因素复核。

### 3.2 密码强度显示

新增 `usePasswordStrength`（纯函数评分）与 `PasswordStrength` 组件：

- 检查项：长度 ≥8、含大写、含小写、含数字、含符号；score = 满足项数（0–5）。
- 等级：score ≤2 → 弱（danger），3 → 中（warning），≥4 → 强（success）；密码为空不显示。
- 组件为三段色条 + 文字标签，色值使用设计系统语义令牌；不引入动画。
- 接入：注册页、邀请注册页、重置密码页、用户中心修改密码、管理端添加账号（初始密码）。

仅做「显示」，不改后端密码策略（现有 ≥8 校验与测试密码保持兼容）。

### 3.3 注册完成自动跳转登录

- `RegisterPage` 注册成功：`navigate('/login?email=<邮箱>')` 并提示「注册成功，请登录」；
- `LoginPage` 读取 `?email=` 预填邮箱（不覆盖「记住账号」值，优先级：URL 参数 > 记住的账号）；
- 未验证邮箱的用户登录后，用户中心已有「去验证」提醒，验证流程不失联；邀请注册页已实现跳登录，保持不变。

### 3.4 记住账号 / 记住密码

- 登录页新增两个默认未勾选的复选框：**记住账号**、**记住密码**；勾选「记住密码」时自动勾选「记住账号」。
- 存储：`localStorage` 键 `lipass.remember.account` / `lipass.remember.password`；仅在**登录成功**后写入（登录失败/放弃 2FA 不落盘）；取消勾选则删除对应键。
- 加载：进入登录页时读取并预填账号与密码、还原勾选状态。
- 登出不清除记忆（语义即「记住」）。

安全影响与缓解：本地明文保存密码会被同源 XSS 读取。默认关闭、仅成功登录后写入、生产 CSP `script-src 'self'`（无 inline）已大幅压缩 XSS 面；仍建议用户优先使用浏览器自带密码管理器。若后续需要更强保障，可改为「仅记住账号 + 浏览器密码管理器（`autocomplete`）」。

## 4. 接口 / 数据模型变更

- 无数据模型变更；新增 `POST /api/v1/me/step-up/send`。
- 行为变更：三个注销/删除端点必须携带 `current_password + stepup_method + stepup_code`，窗口不再豁免。

## 5. UI 设计

遵循 [MASTER.md](../../../design-system/lipass/MASTER.md) / [BRAND.md](../../../design-system/lipass/BRAND.md)：

- 密码强度条：`rounded-full` 小色条，语义色 danger/warning/success，文字 `text-xs`；
- 记住选项：与现有「记住我」同款复选框（`h-4 w-4 accent-primary`）；
- 注销弹窗：密码框 + 2FA 方式单选 + 验证码框始终必填，提供「获取邮箱验证码」按钮与 60 秒重发冷却。

## 6. 验收标准

- 三个注销/删除端点：缺密码/缺 2FA/密码错/验证码错 → 400（限流触发 429）；密码 + 任意 2FA 正确 → 成功；其余敏感操作窗口内仍可免密；
- 前端注销/删除弹窗要求密码 + 2FA 验证码，支持发送邮箱验证码；
- 密码强度：各表单按评分显示 弱/中/强，空密码不显示；
- 注册成功跳转 `/login?email=...`，登录页预填邮箱；
- 记住账号/密码：勾选后成功登录落盘，刷新页面回填；取消勾选清除；登录失败不落盘；
- 后端全量、前端 `tsc/lint/test/build` 全绿。

## 7. 风险与回滚

- 记住密码为本地明文存储，风险已在上文说明；回滚即移除该功能与清理键。
- 注销双因素复核是行为收紧，无数据迁移；上线后用户注销需同时输入密码与验证码。
