# 登出语义优化设计：登出 SSO / 登出本网站

日期：2026-08-16
状态：已实施

## 1. 目标

把「登出」这一动作的两层语义显式写清楚，消除当前 UI 与文档中的含糊表述：

- **登出 SSO（全局单点登出）**：退出门户会话，并通过回程登出 / 浏览器串跳让所有已授权网站一并退出。
- **登出本网站（本地登出）**：只结束当前网站的本地会话，门户与其它授权网站保持登录。

交付：

1. RP 发起登出的门户确认页提供两个语义明确的选项，替换现在「确认退出 / 取消」的含糊按钮。
2. 演示站（RP 侧）分别演示两种登出动作。
3. 对接指南 §7 用统一术语写清两种语义及各自的实现方式。

## 2. 现状与约束

现状（2026-08-15 联邦登出落地后）：

| 路径 | 现状 | 语义 |
| --- | --- | --- |
| `POST /api/v1/auth/logout`（门户用户中心「退出登录」） | 吊销门户会话 → 回程分发 `logout_token` → 无回程网站串跳漏斗 | 登出 SSO |
| `GET /oauth2/end-session`（RP 发起登出） | 校验回跳白名单后进入 `/logout/confirm` 确认页 | 登出 SSO（待确认） |
| `POST /api/v1/oauth/logout-requests/{id}/confirm` | 吊销门户会话 + 回程分发 + 回跳 | 登出 SSO |
| `POST /api/v1/oauth/logout-requests/{id}/cancel` | 不碰门户会话，仅回跳 | 实际是「仅登出本网站」，但名为 cancel，UI 标签「取消」未解释后果 |
| 演示站 `POST /logout` | 清本地会话后 302 到 end-session | 登出 SSO（演示站没有「仅本地登出」入口） |

约束：

- 遵循 OIDC RP-Initiated Logout 规范：`end-session` 一旦进入即表示要退 IdP；「登出本网站」不应调用 `end-session`，由 RP 自行清本地会话。
- IdP 无法清第三方网站 Cookie：确认页上「仅登出本网站」只能保证**保留门户会话**并回跳，当前网站的本地清理由该网站在跳转前完成。
- 这是安全产品：保留会话、吊销会话、回程通知等防护不变；仅重命名内部端点与调整文案，不改变令牌/审计链路强度。
- 品牌显示名 `Li&Pass`，技术标识 `lipass`；文案用中文，术语统一。

## 3. 方案与取舍

### 3.1 术语统一

| 术语 | 含义 | 触发路径 |
| --- | --- | --- |
| 登出 SSO | 退出门户会话 + 通知所有已授权网站退出 | 门户「退出登录」、确认页「登出 SSO」、演示站「登出 SSO」 |
| 仅登出本网站 | 只结束当前网站本地会话，门户保持登录 | 演示站「登出本网站」、确认页「仅登出本网站」 |

### 3.2 后端

把确认页的 `cancel` 端点重命名为语义明确的 `local-only`：

- `POST /api/v1/oauth/logout-requests/{request_id}/local-only`：行为与旧 `cancel` 一致——不吊销门户会话、删除待确认请求、返回回跳地址。
- 不保留 `/cancel` 别名：该端点仅本项目前端调用，外部接入方不可见，属于内部 API。

取舍：

- 方案 A（保留 `cancel` 名，只改 UI 文案）：改动最小，但代码语义与 UI 长期分裂，后人难维护。弃用。
- 方案 B（重命名 `local-only` + 别名兼容旧路径）：兼容旧前端，但引入两条等价路径与测试负担。弃用。
- 方案 C（重命名 `local-only`，前后端同步升级）：代码与文案语义一致，改动集中。选用。

不在本次范围：给门户「退出登录」增加二次选择（它天然就是登出 SSO，已有「退出所有设备」管理其余设备）；给 `local-only` 增加审计（旧 `cancel` 无审计，本次不改审计覆盖，避免无设计地扩审计事件表）。

### 3.3 前端确认页

`/logout/confirm` 两个选项替代「确认退出 / 取消」：

- 主选项「登出 SSO」：危险样式，调用 `/confirm`。说明：退出门户并通知所有通过门户登录的授权网站一并退出。
- 次选项「仅登出本网站」：次要样式，调用 `/local-only`。说明：门户与其它网站保持登录，仅返回 {clientName}；该网站的本地会话由该网站在跳转前自行结束。

### 3.4 演示站（RP 侧）

登录后两个按钮：

- 「登出本网站」：`POST /local-logout`，只清 Flask 会话，回演示站首页。
- 「登出 SSO（退出所有网站）」：`POST /logout`，清本地会话后 302 到 `end-session`（保留现行为）。

### 3.5 文档

`docs/oidc-integration.md` §7 增补「两种登出语义」小节：明确 RP 侧本地登出不应调用 `end-session`；只有「登出 SSO」才走 RP 发起登出；确认页两个选项的后果。CHANGELOG「行为变更」区记录端点重命名与文案变化。

## 4. 接口变更

| 接口 | 变更 |
| --- | --- |
| `POST /api/v1/oauth/logout-requests/{request_id}/cancel` | 重命名为 `/local-only`，行为不变 |
| 前端 `oauthApi.cancelLogoutRequest` | 重命名为 `oauthApi.localOnlyLogoutRequest`，指向新端点 |
| 演示站 `POST /logout` | 不变（登出 SSO） |
| 演示站 `POST /local-logout` | 新增（登出本网站） |

无数据库迁移、无发现文档变化（`end_session_endpoint` 等不变）。

## 5. 安全影响

- 会话吊销、回程 `logout_token` 分发、回跳白名单校验均不改变。
- 端点重命名不引入新权限面：`local-only` 与旧 `cancel` 同样依赖随机 `request_id`（256 位）防枚举。
- 「仅登出本网站」明确保留门户会话，用户从网站退出后 SSO 仍在，属于预期的本地登出语义；文档中提示 RP 需自行清理本地会话。

## 6. UI 设计

沿用 `AuthShell` + 现有卡片样式（`rounded-xl border border-border bg-surface-2/60`），危险主操作用 `btn btn-danger`，次要操作用 `btn btn-secondary`；文案对齐设计系统的中文语气。动效沿用现有 `animate-fade-up`，尊重 `prefers-reduced-motion`（由现有全局样式保障）。

## 7. 验收标准

- 确认页展示「登出 SSO」「仅登出本网站」两个选项及各自后果说明，无「取消」。
- 点「登出 SSO」：门户会话吊销（`/api/v1/me` 401），回程分发发生，回跳地址正确。
- 点「仅登出本网站」：门户会话保留（`/api/v1/me` 200），回跳地址正确，不触发回程分发。
- 演示站登录后可见「登出本网站」「登出 SSO（退出所有网站）」两个按钮；前者只清本地会话、不回 IdP，后者走 `end-session`。
- 后端全量测试、前端 `tsc/lint/test/build` 全绿。
- 对接指南 §7 与 CHANGELOG 更新完成。

## 8. 风险

- 旧前端缓存与新后端端点不匹配：`local-only` 上线后旧页面点「取消」会 404。前端与后端同一编排内发布，无灰度窗口需求；如需灰度可临时保留别名（本次不做）。
- 文案歧义：确认页「仅登出本网站」需注明网站本地清理由其自行完成，避免用户误以为门户代清第三方 Cookie。
