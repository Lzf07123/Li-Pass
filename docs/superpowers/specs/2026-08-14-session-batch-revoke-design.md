# 会话监控批量下线设计

- 日期：2026-08-14
- 状态：已实施完成（2026-08-14）
- 范围：管理后台会话监控新增「批量下线」与「全部下线」

## 1. 目标

在已有「单会话强制下线」的基础上，为管理员提供批量操作：勾选多个在线会话批量下线，以及一键下线除当前会话外的全部在线会话，用于快速处置异常登录。

## 2. 接口设计

| 方法 | 路径 | 语义 |
| --- | --- | --- |
| `POST` | `/api/v1/admin/sessions/batch-revoke` | 请求体 `{"session_ids": [uuid, ...]}`（1–200，去重）。当前会话、已下线、不存在的会话自动跳过，不视为错误 |
| `POST` | `/api/v1/admin/sessions/revoke-all` | 无请求体。先清理过期/空闲超时的“僵尸”会话（与列表口径一致），再下线除当前会话外的全部在线会话 |

响应统一为 `{"revoked": n}`，批量接口额外返回 `{"skipped": m}` 表示被跳过的数量。跳过而非报错的原因：会话列表在读取时会把过期会话懒吊销，前端持有的选择可能已过期，报错会让批量操作变得脆弱。

## 3. 前端交互

- 表格首列新增复选框；表头「全选会话」只勾选已加载且非当前会话的行，当前会话复选框禁用。
- 选中后表格上方出现操作栏：「已选 N 个会话」「批量下线」「取消选择」；搜索、刷新、下线成功后清空选择。
- 头部新增红色「全部下线」按钮，无在线会话时禁用；两者均需在确认弹窗中二次确认。
- 下线成功以 `revoked` 实际数量提示，之后自动刷新列表。

## 4. 审计与安全

- 审计动作：`admin_batch_revoke_session`（detail 记录 count、skipped、emails、user_ids）与 `admin_revoke_all_sessions`（detail 记录 count）。
- 当前会话始终不可被下线：单个接口继续返回 400，批量/全部接口静默跳过，避免管理员误踢自己导致立即登出。
- 频率限制：批量/全部下线按管理员维度限流（`ADMIN_SESSION_REVOKE_RATE_LIMIT` 默认 30 次/分钟，窗口 `ADMIN_SESSION_REVOKE_RATE_WINDOW_SECONDS` 默认 60 秒），超限返回 429 并记审计，兜底大规模下线滥用。
- 与用户管理批量操作一致：会话下线可逆（用户重新登录即可），因此不需要「当前密码」复核。

## 5. 测试

- 后端：批量下线、跳过当前/不存在/已下线会话、空列表 422、全部下线保留当前会话、非管理员 403、审计落库。
- 后端（安全审查补充）：批量/全部下线触发频率限制返回 429；配置项默认值与非法值校验。
- 前端：全选排除当前会话、批量确认流程与请求体、全部下线流程、无会话时按钮禁用。

## 6. 安全审查结论（2026-08-14）

- CSRF：带会话 Cookie 的写请求由全局 Origin 校验中间件统一拦截，两个新接口同样被覆盖。
- 越权：路由级 `get_current_admin`，非管理员返回 403（有测试）；接口不返回其他用户的敏感信息，仅返回数量。
- 自我保护：当前会话在单个接口返回 400、在批量/全部接口被排除，管理员不会误踢自己。
- 注入：`session_ids` 为 UUID 类型且走参数化 `in_` 查询；前端为 React 转义渲染，无 XSS 风险。
- 审计：操作者、来源 IP 与受影响邮箱均留痕；全部下线只记 count 以控制审计体量。
- 已知权衡：单个「强制下线」接口沿用原有无限流设计（逐目标、低放大倍数），本次未改动。
