# 管理后台「用户管理」刷新按钮设计

## 背景

管理后台的用户管理面板（`AdminUsersPanel`）只在挂载时加载一次用户列表，后续仅通过搜索/筛选触发重新加载，头部没有手动刷新入口。而会话监控、审计日志、数据统计、系统信息四个面板均已提供统一的「刷新」按钮。管理员在别的终端修改数据后，无法在不改筛选条件的情况下重新拉取列表。

## 目标

在用户管理头部右侧按钮组最右端新增一个「刷新」按钮，与其他面板保持一致。

## 方案

采用面板内既有统一模式：`useAsyncAction` + `AsyncButton`。

- 位置：头部右侧按钮组（添加账号 / 邀请注册 / 批量邀请 / 两个筛选器）最右端，紧跟搜索表单之后。
- 行为：点击调用现有 `load(query, statusFilter, roleFilter)`，按**当前搜索词与筛选条件**重新拉取列表；不清空勾选状态。
- 状态：加载中按钮由 `AsyncButton` 的 pending 状态自动禁用，防止重复点击。
- 反馈：成功后 Toast「用户列表已刷新」；失败沿用统一错误 Toast（「刷新失败」）。

不采用普通 `<button>` 直连 `load` 的备选：缺少加载态、可重复点击，且与既有面板模式不一致。

## 测试

新增 `frontend/src/__tests__/AdminUsersPanel.test.tsx`：

1. 渲染面板并 stub `fetch`，点击「刷新」后断言 `adminUsersApi.list` 对应请求被再次发出，且保持当前查询参数。
2. 失败路径断言展示「刷新失败」错误提示。

## 非目标

- 不新增自动轮询、不新增多个刷新按钮。
- 不改变搜索/筛选/分页交互与选中语义。
