# 活跃对接网站会话感知设计

日期：2026-08-16
状态：已实施

## 1. 目标

提升门户对「活跃对接网站会话」的感知：准确维护「用户 × 客户端」登录链接的生命周期，并在应用广场向用户展示每个网站当前是否有活跃登录（几台设备），为取消授权/门户登出的下线通知提供可靠依据。

## 2. 现状与问题

- `oidc_client_sessions` 记录「某门户会话登录过某网站」（`sid = str(session_id)`），仅在换令牌时创建，`revoked_at` 全代码库从未被写入。
- 门户会话被撤销时已向对应网站派发回程登出，但链接不吊销——后续把已下线的关系误判为「活跃」。
- 重新授权时若旧链接存在（含已吊销），不会再新建，导致状态与事实脱节。
- 应用广场只展示授权关系，不展示当前是否活跃登录。

## 3. 方案

1. **链接生命周期**：
   - 新增 `revoke_session_links(db, session_ids)` 与 `revoke_user_links(db, user_id)`。
   - 门户会话撤销路径（用户单会话撤销、退出所有设备、门户登出、管理员单/批量/全部下线）在派发回程通知后同步吊销对应链接。
   - 门户登出按用户通知全部授权，故吊销该用户全部链接（其它设备上网站已同时被通知下线）。
   - 换令牌时若链接存在但已吊销，重新激活（`revoked_at=None`）。
2. **活跃计数**：`GET /api/v1/apps` 每个应用返回 `active_sessions`——该用户在该客户端上「链接未吊销且门户会话未撤销、未过期」的条数。
3. **前端**：应用广场卡片展示「已登录 · N 台设备」或「未登录」徽标。

## 4. 安全与一致性

- 不改动回程登出分发时机与令牌内容；仅在派发之后吊销链接，不丢失下线通知。
- 已通知过下线的旧链接不再被误认为活跃，避免重复通知与误导展示。
- 不新增对外 OIDC 契约；仅内部状态与展示。

## 5. 验收

- 撤销会话/门户登出/管理员下线后，对应链接 `revoked_at` 被置位；应用广场计数下降。
- 重新授权后链接重新激活、计数恢复。
- 应用广场按链接活跃度展示徽标。
- 后端全量、前端 tsc/lint/test/build 全绿。
