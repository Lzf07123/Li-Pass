## 1. 品牌定位与人格

### 1.1 一句话定位

Li&Pass 是「一次注册，通行所有授权网站」的**可信身份门户**——用户在这里完成身份验证，然后安静地通行到各个授权站点。品牌的第一任务是建立信任，第二任务是让信任显得毫不费力。

### 1.2 品牌人格

| 维度 | 描述 |
| --- | --- |
| 人格关键词 | 安全、可信、克制、专业、流畅 |
| 人格比喻 | 一位可靠的守门人：不说废话、不制造惊吓，把门打开后安静退到一旁 |
| 品牌承诺 | 一次验证，永久通行；每一步都被审计、每一次授权都明示 |
| 避免成为 | 花哨的营销页、吓唬人的安全警告、冷冰冰的政务系统 |

### 1.3 品牌隐喻：通行的几何暗线

品牌氛围层的所有装饰元素都来自同一个隐喻——**身份凭证安全地穿行**：

| 符号 | 隐喻 | 用法 |
| --- | --- | --- |
| 细直线 | 连接与路径（通行） | 背景层低频穿行 |
| Z 形折线 | 门径 / 路线转折 | 品牌签名形，认证页最多 |
| 方块 | 凭证 / 授权票据 | 往复钟摆，稳定存在感 |
| 锁钥组合 | 安全与钥匙 | 稀有元素，仅在信任关键时刻出现 |
| 圆点光斑 | 会话 / 数据包 | 盘旋公转，表示活跃但安静 |

这些符号**永远低透明度、永远在背景层**，是「品牌暗线」而非「主角」。它们呼应 slogan 里的「通行」，而不是装饰性堆砌。

## 2. 品牌设计总思路（五大原则）

1. **信任优先（Trust First）**：色彩、字体、徽章、文案都要传递「安全但不唬人」。安全提示清晰可行动，避免恐吓式文案；关键安全能力（2FA、审计、强制下线）用可见但克制的方式呈现。
2. **淡色科技感（Light-Toned Tech）**：全淡色系 + 海玻璃主色强调，不用霓虹渐变、不用粉色系、不做大面积重色。科技感来自雾面粉彩层次、干净精确与动效质感。
3. **以动衬静（Motion as Breath）**：入场动效是一次性「打招呼」，环境循环动效是恒定的「呼吸」。所有氛围动效必须极慢、极淡、GPU 加速、永不阻塞交互；能关掉（`prefers-reduced-motion`），能在低端设备上自动降级。
4. **单一事实来源（Single Source of Truth）**：颜色、间距、阴影、动效时长只存在 `index.css` 的令牌里；品牌文案与资源只存在 `lib/brand.ts` 里。组件内禁止硬编码 hex 值与文案。
5. **无障碍与节能（Accessible & Efficient）**：正文对比度 ≥ 4.5:1，键盘焦点始终可见，可点击目标 ≥ 44×44px 或等价热区，动效尊重系统减弱偏好，移动端减量省电。

| lilac | `#7A6FC4` / `#EDEAFB` | `#A9A2E8` / `rgba(169,162,232,.18)` | 邮箱变更、TOTP |

- 强调色只做装饰，绝不替换 warning/destructive——错误、删除、警告永远走语义色；
- strong 取雾面 600 级（浅色）/300 级（深色），soft 底上文本对比 ≥ 4.5:1；
- 实体 → 色相用稳定哈希分配（`accentFor(id)`），刷新页面不跳色；
- 强调色合计 ≤ 15% 可视面积，主色仍占彩色面积大头；正文永远 foreground/muted。

#### 用色比例与规则

- 比例约 **60/30/10**：中性色（背景/表面/边框）≈ 60%，卡片与内容表面 ≈ 30%，主色 + 语义色 ≈ 10%。主色永远是小面积强调，不做大面积主色背景。
- 强调色板属于「主色 + 语义色」之外的装饰层：合计 ≤ 15%，只用于图标瓦片、徽章、图例、分区规则线、图表系列与 Bento 标签等小面积，不铺色块。
- 语义色（成功/警告/危险）只表达状态，不用于装饰。
- 禁用清单：**粉色系（粉红/品红/玫瑰）**、大面积重色背景、霓虹渐变、纯黑 `#000`、低对比灰字、装饰性色块。低透明度的氛围点缀除外（如极光背景的水绿/冰蓝光斑、认证卡片的粉彩描边），它们只出现在背景与描边层，不作为大面积主色背景。
- 所有文本组合需满足 WCAG AA（正文 ≥ 4.5:1；大字号与 UI 组件 ≥ 3:1）。

### 3.2 字体与排版

**字体栈（已在 `index.css` 定义）：**

```css
--font-sans: "Inter", ui-sans-serif, system-ui, -apple-system, "Segoe UI",
  Roboto, "Helvetica Neue", Arial, "Noto Sans", "PingFang SC",
  "Hiragino Sans GB", "Microsoft YaHei", sans-serif;
```

- **原则：不加载远程字体**。优先本机 Inter，未安装时回退系统字体；中文依次回退 PingFang SC / 微软雅黑。这保证内网与国内网络环境下零字体请求、首屏无闪烁。
- 规则库的「Corporate Trust」组合（Lexend 标题 + Source Sans 3 正文）可读性更佳，属于**可选项**：如需更强的品牌辨识度，可自托管 Lexend 仅用于页面标题（`font-display: swap` + `subset`），正文保持现有栈。启用前需评估字体体积与构建流程，不做 Google Fonts CDN 引用。

#### 字号层级

| 层级 | 尺寸 | 用法 |
| --- | --- | --- |
| 页面标题 | 22px / semibold | 认证页标题（`AuthShell`） |
| 区块标题 | 16–18px / semibold | 卡片标题、面板标题 |
| 正文 | 14px / regular | 默认正文、表单、表格 |
| 头部/辅助 | 15px | 顶栏品牌名 |

- 数字与状态数值可加宽（tabular-nums）以保证对齐稳定。

### 3.3 图形语言与品牌符号

- 品牌装饰符号（Z 形折线、方块、直线、锁钥、光斑）必须满足：几何、无渐变、描边或纯色低透明度、无阴影、无滤镜。
- Z 形折线是品牌签名形：认证页可出现在背景层（2–3 个），其余页面最多 1 个；绝不作为功能图标。
- 符号不与文字、按钮、表格发生可读性冲突（见第 4 章禁飘区规则）。

### 3.4 Logo 与图标

**Logo**

- 文件：`frontend/public/brand-logo.webp`（透明背景 512×512），favicon 用 `favicon.webp`。
- 最小显示尺寸 32×32px（顶栏 32px、认证页 48px）；周围留白 ≥ 1/4 图标边长。
- 禁止改色、旋转、加描边、拉伸、叠加文字。深色/浅色背景均使用同一 Logo（透明底），不得反白处理。

**图标**

- 图标颜色继承 `currentColor`，状态图标使用语义色（成功绿 / 警告黄 / 危险红）。

## 4. 品牌氛围动效：环境呼吸感（循环飘动）

### 4.1 设计思路：从「入场效果」升级为「环境呼吸感」

入场动画（fade-up、blur-in）只发生在页面出现的一瞬间；品牌氛围真正需要的是**恒定背景音**——极慢、极淡、永不停止的几何元素循环，让页面「活着」但不打扰操作。核心哲学：

- **永不退场**：所有飘动元素进入无限循环，完成一次穿越后从起点重新开始（或无缝折返）。
- **交错节奏**：同一页多个元素在 `animation-delay` 与速度上错峰，形成此起彼伏的自然感。
- **用户无感**：极慢、极淡，操作时几乎注意不到，离场后留下「这个页面很流畅」的潜意识记忆。
- **永不阻塞**：只动 `transform/opacity`（GPU 合成），严禁触发回流；元素 `pointer-events: none`。

### 4.2 现状盘点（实事求是）

> **实施状态（2026-08-14）：** 本章的「循环飘动」思路已以纯 Canvas 复合运动形式落地（水平匀速漂移 + 垂直正弦摆动），组件 API 与分页接入标准见 [MASTER.md](./MASTER.md) 的「环境呼吸层」与 `docs/superpowers/specs/2026-08-14-ambient-background-design.md`。下方 DOM/CSS 四模式骨架作为设计参考保留，实现以 Canvas 版为准。

| 项目 | 当前实现 | 结论 |
| --- | --- | --- |
| 认证页氛围 | `AuroraBackground` 三枚弥散光斑，`infinite alternate` 16/20/24s 漂移 | 已有「呼吸底」，可保留 |
| 几何飘动元素 | 尚未实现（无 Z 形/方块/锁钥） | 需按本章落地 |
| 分页氛围策略 | 各页面未区分浓度 | 需按 4.5 分层 |
| 移动端降级 | 无专项 | 需按 4.8 落地 |

> **适配说明**：原动效方案假设登录页为「左深右白分栏」、后台为「侧边栏」。当前代码事实是：认证页为**居中单卡片**（`AuthShell` + `max-w-md`），管理后台为**顶部标签页**（`AdminPage` 的 `TABS`）。本章以现有布局为准改写分区与数量，分栏/侧栏版可作为后续视觉升级的可选项，不纳入本次执行标准。

### 4.3 四种循环轨迹模式

| 模式 | 运动逻辑 | 关键帧示意 | 适用元素 |
| --- | --- | --- | --- |
| A 水平无限穿行 | 屏外左侧进入，水平穿越，移出右侧后瞬间重置到起点；边缘淡入淡出 | `0% { translateX(-20%); opacity: 0 }` → `10% { opacity: 1 }` → `90% { opacity: 1 }` → `100% { translateX(120%); opacity: 0 }` | Z 形飘片（大）、几何线条 |
| B 往复钟摆 | 固定距离内来回（`alternate`），不离开屏幕 | `0% { translateX(0) }` → `100% { translateX(300px) }` | 正方飘块、平行飘块、Z 形（小） |
| C 正弦波形 | 水平匀速 + 垂直正弦起伏，穿越后重置 | 外层 `translateX` 匀速，内层 `translateY` 用 `ease-in-out` 分段模拟 sin | Z 形飘片、锁钥组合 |
| D 盘旋公转 | 绕自身中心或屏幕某点做 360° 旋转 / 椭圆公转 | `0% { rotate(0) translateX(80px) }` → `100% { rotate(360deg) translateX(80px) rotate(-360deg) }` | 圆点光斑、锁钥组合（稀有） |

### 4.4 全局执行标准（统一总控表）

| 元素 | 轨迹 | 单次周期 | 循环 | 延迟（随机范围） | 透明度 | 缩放 |
| --- | --- | --- | --- | --- | --- | --- |
| Z 形飘片（大） | A | 45s | infinite | 0–15s | 0.06–0.12 | 0.8–1.2 |
| Z 形飘片（小） | B | 30s | infinite | 0–10s | 0.10–0.18 | 0.5–0.8 |
| 正方飘块 | B | 40s | infinite | 0–20s | 0.06–0.10 | 0.6–1.0 |
| 平行飘块 | A（反向） | 55s | infinite | 0–25s | 0.06–0.10 | 0.7–1.1 |
| 圆点光斑 | D | 25s | infinite | 0–8s | 0.15–0.25 | 0.8–1.5 |
| 几何线条（长） | A | 60s | infinite | 0–30s | 0.04–0.08 | 1.0 |
| 锁钥组合 | C | 90s | infinite | 0–45s | 0.04–0.06 | 0.9–1.1 |

**执行铁律**：`animation-direction` 默认 `normal`（穿行）或 `alternate`（钟摆）；`animation-fill-mode: both`，保证延迟期间保持初始状态；所有元素 `pointer-events: none` + `will-change: transform, opacity`。

### 4.5 分页配置（适配现有页面结构）

#### 认证页（登录 / 注册 / 邀请注册 / 找回 / 重置 / 邮箱验证）——迎宾氛围，最丰富

- **背景层**（卡片之后）：保留 `AuroraBackground` 三枚光斑；新增 2 个 Z 形飘片（大，A）、2 个 Z 形飘片（小，B）、1 个正方飘块（B）、2 个圆点光斑（D）、1 条几何线条（A）、可选 1 个锁钥组合（C，仅登录/授权确认页）。
- **禁飘区**：居中卡片及其上方 120px 范围内，元素透明度强制降至 0.03 或直接避开该水平带；卡片表面为不透明 `bg-surface`，天然遮蔽背景元素。
- **焦点联动**：表单容器监听 `focusin/focusout`，聚焦时给容器加 `.is-typing`，所有飘动元素周期 × 2（速度减半），失焦恢复；减半后仍为无限循环。

#### 用户中心（`/dashboard`）——活跃但不打扰

- **页面背景层**：4 个 Z 形飘片（大小混合）+ 6 个圆点光斑（D，沿卡片间隙中线公转，模拟「数据在服务间跳跃」）。
- **卡片区域**：仅允许透明度 < 0.06 的极淡几何线条穿行；任何元素不得遮挡卡片内文字与按钮，与卡片矩形交集时透明度强制降至 0.02。
- **顶栏下缘**：2 个平行飘块反向穿行，沿顶栏底部 8px 处滑动，像「数据流从导航栏流出」。
- **滚动联动**：滚动不暂停循环；滚动越快，飘动越快（0.5x–1.5x），模拟「风吹数据流」。实现见 4.7。

#### 管理后台（`/admin`）——克制的光效点缀（V2.2 起按用户要求接入）

当前为顶部标签页布局，按此适配：

- **内容区角落**：2 个圆点光斑（D），轨道半径 150px，周期 60s，透明度 0.04。
- **内容区侧缘**：1 个 Z 形飘片（小）改为**垂直钟摆**（`translateY` 往复），如「指针沿标签栏边缘滑动」，不水平穿行。
- **光效层（V2.2）**：接入淡版极光层（`aurora-soft`）+ 科技氛围层（`TechAmbience soft`），
  光束与网格只在页面间隙、页边与卡片之间可见。
- **表格区域**：表格/卡片仍为不透明 `bg-surface`，飘动元素不入侵表内文字，
  `pointer-events: none` + 布局约束双保险，可读性绝对优先。
- **分页器下方**：1 条几何线条水平往返，宽度 60% 居中，透明度 0.05。

#### 授权确认页（`/consent`）——信任时刻，氛围减半

用户在此授权，氛围必须更安静：仅 2 个 Z 形飘片（小）+ 2 个圆点光斑，透明度取全局下限，无锁钥组合以外的任何强符号。授权卡片区域禁飘规则与认证页一致。

### 4.6 循环节奏的「错峰」算法

避免多个元素同时穿到屏幕中央造成拥堵：

```text
animation-delay = (元素索引 / 总元素数) × 最大错峰时间 + 随机余量(±2s)
```

例：页面 10 个飘动元素、总周期基准 40s、最大错峰 20s → 元素 1 延迟 0s、元素 2 延迟 2s、……、元素 10 延迟 18s，各加 ±2s 随机余量。效果：10 个元素均匀分布在 20s 时间轴上，不会同时穿越中央。

### 4.7 交互联动实现要点

**焦点减速（认证页）**

```css
.is-typing .float-element {
  animation-duration: calc(var(--base-duration) * 2) !important;
}
```

**滚动风速（用户中心）**

```js
window.addEventListener("scroll", () => {
  const speed = Math.min(Math.abs(window.scrollY - lastScrollY) / 10, 1.5);
  document.documentElement.style.setProperty("--scroll-speed", speed);
});
```

```css
.float-element {
  animation-duration: calc(var(--base-duration) / var(--scroll-speed, 1));
}
```

基础骨架（一个 Z 形飘片）：

```html
<div class="float-element type-z" style="--duration: 45s; --delay: 5s"></div>
```

```css
.float-element {
  position: absolute;
  pointer-events: none;
  will-change: transform, opacity;
  transform: translate3d(0, 0, 0);
  animation: float-across var(--duration) linear var(--delay) infinite both;
}

@keyframes float-across {
  0% {
    transform: translateX(-150px) translateY(0);
    opacity: 0;
  }
  10%,
  90% {
    opacity: var(--opacity);
  }
  100% {
    transform: translateX(calc(100vw + 150px)) translateY(var(--wave-offset, 0));
    opacity: 0;
  }
}
```

### 4.8 性能、无障碍与移动端降级

- 只动画 `transform/opacity`；动画元素禁用 `filter` 与 `box-shadow`（现有极光光斑已刻意不做大尺寸 blur，同样原则）。
- `prefers-reduced-motion: reduce` 时，所有循环与入场动画缩短为 `0.01ms` 单帧（全局规则已内置）。
- 移动端减量（循环仍生效）：

| 设备 | 最大元素数 | 周期倍率 | 透明度倍率 |
| --- | --- | --- | --- |
| 桌面（≥1024px） | 不限 | 1.0x | 1.0x |
| 平板（768–1023px） | ≤15 | 1.2x（慢 20%） | 0.8x |
| 手机（<768px） | ≤6 | 1.5x（慢 50%，省电） | 0.5x |

- 手机端仅保留：2 个 Z 形飘片（穿行）+ 2 个圆点光斑（盘旋）+ 2 条几何线条（穿行）。

## 6. 文案与语调

- **清晰优先**：先告诉用户发生了什么、下一步做什么。「我们已向 your@email.com 发送验证码」优于「验证码已发送」。
- **动词开头的按钮**：登录、注册、继续授权、保存更改、强制下线。
- **不用感叹号、不用网络流行语、不用拟人化过度**。信任场景需要平静的确定性。
- **错误信息可行动**：「密码错误，请重试或点击忘记密码」优于「登录失败」。
- **安全语言诚实但不吓唬**：「检测到新设备登录」直接说明事实并提供处置（下线会话），不做恐吓式红色警报。
- **数字与时间精确**：剩余尝试次数、锁定倒计时、验证码有效期都要给出具体数值。

### 7.2 变更流程

1. 新视觉决策先在 BRAND.md 表达意图与理由，再在 `index.css` 以令牌落地。
2. 新页面复用 `AuthShell` / `AppHeader` / `card` / `btn` 等既有模式；确需新模式时先更新 MASTER.md 的页面模式清单。
3. 任何 PR 涉及视觉，需对照本报告第 8 章差距表与 MASTER.md 的 Pre-Delivery Checklist 自查。
4. 动效落地统一走第 4 章标准，禁止页面级硬编码动画参数。
